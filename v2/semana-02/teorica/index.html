Game loop

Un juego corre en bucle

No es un programa que va de arriba a abajo y termina. Corre constantemente mientras el juego esté abierto.

2 · Lógica

Todo en pantalla · y repite ↺

❤️ Como un corazón: cada latido es un frame. Si late 60 veces por segundo, el juego se actualiza 60 veces por segundo.
Frames por segundo

60 FPS = 60 veces por segundo

Godot corre por defecto a 60 FPS. Todo el código dentro del game loop se ejecuta 60 veces por segundo.

Arranque del nodo

_ready(): el momento de preparación

Godot la llama una sola vez, justo cuando el nodo entra a la escena. Sirve para configurar todo antes de que empiece la acción.

extends Node2D

var vida = 100
var nombre = "Héroe"

func _ready():
	position = Vector2(100, 300)
	print("=== Juego iniciado ===")
	print("Vida: " + str(vida))
_ready()

Regla de oro

🎤 _ready() es como el discurso de apertura: se dice una vez, al principio, y después el juego toma su curso.

👐 Mini práctica

Cambiar la posición inicial y los valores de las variables, ejecutar el proyecto y observar cómo cambia el punto de partida. La idea: entender que _ready() define el estado inicial del mundo.

El corazón

_process(delta): cada frame

Godot la llama en cada frame. A 60 FPS, se ejecuta 60 veces por segundo. Es el corazón del juego en movimiento.

func _process(delta):
	print("Estoy corriendo constantemente")

Esto llena la consola sin parar — el motor la llama una y otra vez.

La diferencia clave

_ready() vs _process()

FunciónCuándoPara qué
_ready()Una vez, al entrar a la escenaInicialización, posición y valores de partida
_process(delta)Cada frame (~60/seg)Lógica continua: movimiento, input en tiempo real
Acá muchos hacen “click” con el game loop: uno se imprime una vez, el otro sin parar.
Hay un tercer hermano

_process vs _physics_process

FunciónCuándo se llamaPara qué
_process(delta)En cada frame dibujado. Si la compu va lenta, menos vecesLógica general: input, UI, animaciones, mover un Node2D
_physics_process(delta)A frecuencia fija: 60 veces por segundo, siempreTodo lo que usa física y colisiones
📏 Regla: si el nodo choca con algo (la semana que viene: move_and_slide()), va en _physics_process(). Todo lo demás puede ir en _process(). Las dos reciben delta y se usan igual.
El concepto clave

El problema de mover sin delta

func _process(delta):
	position.x += 5

Suma 5 píxeles… ¿por frame?

MáquinaResultado
60 FPS5 × 60 = 300 px/seg
30 FPS5 × 30 = 150 px/seg
⚠️ El mismo juego, en distintas máquinas, se comporta distinto. Problema serio.
delta

La solución: multiplicar por delta

delta es el tiempo (en segundos) desde el frame anterior. A 60 FPS ≈ 0.016.

60 FPS200 × 0.016 ≈ 200 px/seg
30 FPS200 × 0.033 ≈ 200 px/seg
 
func _process(delta):
	position.x += 200 * delta

El movimiento queda atado al tiempo real, no a la velocidad de la máquina.

delta · regla

La regla, sin excepción

📏 Cada vez que escriban movimiento dentro de _process(), multiplican por delta. Siempre.

🏠 Analogía

Es como pagar el alquiler por día en vez de una cuota fija. Tenga el mes 28 o 31 días, siempre se termina pagando lo mismo al final.

Antes de mover nada

Un vector es una flecha

Un punto es un lugar: (x, y). Un vector es un desplazamiento: cuánto en X y cuánto en Y. Se dibuja como una flecha, y tiene dos cosas: dirección y largo.

  • (3, 0): tres a la derecha
  • (0, -2): dos hacia arriba (en Godot la Y crece hacia abajo)
  • (3, 4): en diagonal. Su largo es 5 (Pitágoras: √(3²+4²))
En un juego, todo lo que se mueve tiene un vector: hacia dónde va y cuánto. La posición de un nodo también es un vector: la flecha desde el origen hasta él.

El plano de Godot: origen arriba a la izquierda, la Y baja.

Vectores

Con las flechas se puede operar

➕ Sumar = encadenar flechas

Una flecha después de la otra. Se suma X con X e Y con Y. Así se combinan el movimiento del teclado y un empujón, o la gravedad y un salto.

✖️ Multiplicar por un número = estirar

El número no cambia la dirección, solo el largo. Multiplicar por 0.5 la acorta; por un negativo, la da vuelta.

Por eso funciona position += direccion * velocidad * delta: dirección (hacia dónde, largo 1) × velocidad (píxeles por segundo) × delta (qué parte de un segundo pasó).
Vectores · en el motor

En Godot se llama Vector2

extends Node2D
var velocidad = 200

func _process(delta):
	var direccion = Vector2(1, 0)         # derecha
	position += direccion * velocidad * delta

# Direcciones que ya vienen hechas:
#   Vector2.RIGHT = (1, 0)    Vector2.UP   = (0, -1)
#   Vector2.LEFT  = (-1, 0)   Vector2.DOWN = (0, 1)

# La trampa de la diagonal:
var diagonal = Vector2(1, 1)
print(diagonal.length())          # 1.41: ¡41% más rápido!
diagonal = diagonal.normalized()
print(diagonal.length())          # 1.0: misma dirección, largo 1

position también es un Vector2

position.x y position.y son sus dos partes. Por eso position += algo suma flechas: la de donde está más la del paso de este frame.

🧰 Dos herramientas

  • .length(): el largo de la flecha (la distancia)
  • .normalized(): la misma flecha, con largo 1. Para que la diagonal no sea más rápida

Profesionalizar

Input Map: acciones con nombre

❌ Sin Input Map

if Input.is_key_pressed(KEY_D) repetido en 50 lugares. Cambiar la tecla = cambiar 50 líneas.

✅ Con Input Map

Se detectan acciones con nombre (mover_derecha). La tecla se cambia en un solo lugar y todo sigue funcionando.

Se accede en Project → Project Settings → Input Map.
Input Map

Crear una acción nueva

  1. Escribir el nombre: mover_derecha
  2. Clic en Add
  3. Clic en el + de la acción
  4. Presionar la tecla (ej. D)
  5. Confirmar
if Input.is_action_pressed("mover_derecha"):
	position.x += velocidad * delta

Teclado

Movimiento completo (4 direcciones)

func _process(delta):
	if Input.is_action_pressed("mover_derecha"):
		position.x += velocidad * delta
	if Input.is_action_pressed("mover_izquierda"):
		position.x -= velocidad * delta
	if Input.is_action_pressed("mover_arriba"):
		position.y -= velocidad * delta
	if Input.is_action_pressed("mover_abajo"):
		position.y += velocidad * delta
⚠️ En Godot el eje Y está invertido: Y positivo es hacia abajo. Fuente frecuente de confusión.
Teclado · con vectores

Los cuatro if, en una línea

func _process(delta):
	var direccion = Input.get_vector(
		"mover_izquierda", "mover_derecha",
		"mover_arriba", "mover_abajo")
	position += direccion * velocidad * delta

Input.get_vector()

  • Lee las cuatro acciones y devuelve un Vector2
  • Nada apretado: (0, 0). Derecha: (1, 0). Arriba: (0, -1)
  • Dos teclas: (0.7, 0.7), ya normalizado. La diagonal no corre más

El TP arranca con los cuatro if para que se entienda qué pasa; después se pasa a esta versión.
