Antes de exportar

Ordenar el proyecto

res://
├── assets/
│   ├── sprites/
│   ├── audio/
│   │   ├── music/
│   │   └── sfx/
│   └── fonts/

│   ├── personajes/

├── scripts/

Un proyecto ordenado es más fácil de mantener, depurar y compartir. Vale la pena hacerlo antes de exportar.
Organización

Antes de exportar, verificar…

  • Escena principal: Project Settings → Application → Run → Main Scene
  • Ícono y nombre: Application → Config → Icon / Name
  • Sin errores en rojo en la consola al jugar completo
  • Rutas res://: todas las referencias relativas, nunca absolutas
⚠️ Una ruta absoluta (C:\Users\...) funciona en tu máquina pero se rompe al exportar o en otra compu. Siempre res://carpeta/archivo.png.
La clave

Export Templates: el motor compilado

Son los archivos con el motor compilado para cada plataforma. Sin ellos no se puede exportar.

  • Editor → Manage Export Templates → Download and Install
  • Godot baja los compatibles con tu versión

💡 Pesan varios GB. Si la conexión es lenta, descargalos antes de la clase.

Windows

Exportar a Windows (.exe)

  1. Project → Export → Add… → Windows Desktop
  2. Elegir carpeta y nombre (mi_juego.exe)
  3. Export Mode: All Resources
  4. Clic en Export Project
mi_juego/
├── mi_juego.exe  # el ejecutable
└── mi_juego.pck  # los recursos
# Sin el .pck, el .exe no funciona.
Windows

Configuraciones útiles de exportación

OpciónPara qué sirve
Embed PCKFusiona .exe y .pck en un solo archivo. Más cómodo de distribuir, más lento de compilar.
Console WrapperAbre una consola al ejecutar. Útil para debug. Desactivar en la versión final.
IconÍcono del ejecutable. Recomendado: .ico con varios tamaños.
Para distribuir: comprimí el .exe y el .pck juntos en un .zip.
Android

Exportar a Android (.apk): requisitos

Es más complejo (necesita herramientas extra), pero ver tu juego en el celular es muy motivador.

Android SDKVía Android Studio → SDK Manager (SDK Platform + Build Tools)
JDKPara firmar el APK. JDK 17 LTS desde adoptium.net
Configurar en GodotEditor Settings → Export → Android → rutas de SDK y JDK
Android

Clave de debug y exportar

# Generar un keystore de debug (PowerShell):
keytool -genkey -v -keystore debug.keystore \
  -storepass android -alias androiddebugkey \
  -keypass android -keyalg RSA \
  -keysize 2048 -validity 10000

Editor Settings → Export → Android → Debug Keystore → apuntar al archivo.

  1. Project → Export → Add → Android
  2. Unique Name: com.tuestudio.juego
  3. Export Path: mi_juego.apk
  4. Export Project
⚠️ Para instalarlo, activá “fuentes desconocidas” en el celular. El APK de debug sirve para pruebas, no para la Play Store.
Antes de lanzar

Testing y debugging

  • Jugar de principio a fin al menos 3 veces
  • Intentar romperlo: ir a lugares raros, hacer acciones inesperadas
  • Que alguien que nunca lo jugó lo juegue — observar sin ayudar
  • Verificar audio y resolución en el ejecutable
El mejor test es la persona que nunca vio tu juego. Vas a descubrir cosas que jamás imaginaste.
Testing

Resolución y modo de pantalla

# Project Settings → Display → Window:
# - Viewport Width / Height: resolución base (ej: 1280 × 720)
# - Stretch Mode: canvas_items (pixel art) o viewport (UI)
# - Stretch Aspect: keep (mantiene proporción)

# Por código, pantalla completa:
DisplayServer.window_set_mode(DisplayServer.WINDOW_MODE_FULLSCREEN)
# Volver a ventana:
DisplayServer.window_set_mode(DisplayServer.WINDOW_MODE_WINDOWED)

Cómo presentar tu juego

1 · Demo jugable (5 min)

Mostrar el juego funcionando. Explicar el objetivo: ¿cómo se gana o pierde?

2 · Tour técnico (3 min)

Una parte del código que les resultó interesante o difícil. Qué herramienta de Godot usaron.

3 · Reflexión (2 min)

¿Qué fue lo más difícil? ¿Qué agregarían con más tiempo? ¿Qué aprendieron sin esperarlo?

🤝 No es una evaluación, es aprendizaje entre pares: “¿alguien vio algo acá que le gustaría implementar en el suyo?”.
